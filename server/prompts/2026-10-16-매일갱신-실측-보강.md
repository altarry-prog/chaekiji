# 2026-10-16 — 매일 갱신 첫 실측과 보강 · 예시 값 정정 (Claude 생성, 사람 확인)

## 목적
깃허브 액션으로 정보나루 조회분을 매일 받는 일(refresh-today)을 처음 실제로 돌렸다. 저장소 비밀값은 담당자가 깃허브 설정 화면에서 직접 넣었고(이름 NARUKEY), 키는 채팅·코드·파일 어디에도 없다.

## 일어난 일(실측)
1. 1·2회차: 약 2분 뒤 받은 데이터 없이 실패. 깃허브 로그는 밖에서 볼 수 없어 까닭을 몰랐다.
2. 실행 기록을 남기게 고친 3회차: 31회 호출, https로 연결됨. 5종 중 1종(지구 끝의 온실)만 성공, 나머지는 「연결 거절」·「시간 초과」가 섞여 실패.
3. 성공한 1종은 16개관 모두 소장·대출 가능으로 나왔다 — 8/18 픽스처의 「관내 미소장」은 실측이 아니라 책바다 장면용 예시 값이었다.

## 지시 요지와 바꾼 것
- 「코랩을 따로 열지 않아도 되게, 알아서」 → 깃허브 서버가 매일 받게 하고, 도서 목록 파일을 고치면 바로 돌게.
- `naru._get`: 일시 장애 다시 시도·호출 간격·https→http 넘어가기. `refresh_today.py`: 실패 도서 한 바퀴 더, 실행 기록(키 가림), 한국 날짜.
- 예시 값 표시(`_examples`)와 안내문 문구, 시연 웹 v1.12.1(예시 단추는 장면 고정, 직접 찾으면 오늘 자료, ③ 「예시」 배지).

## 검증
- 모의 정보나루(연결 35% 끊김)에서 5종 전부 성공(두 번째 바퀴 포함), 키 원문이 실행 기록·데이터 파일에 없음, 실패 시 기록만 남고 데이터 파일은 쓰지 않음.
- 시험 82건(적합성 48·실험실 14·중계 14·호스트 6) + 중계 점검 15건(https→http 넘어가기 1건 추가) + 시연 웹 시험 17건 통과.

## 남은 확인
- 실제 정보나루에서 다시 시도·간격으로 5종이 모두 받아지는지(이 커밋으로 4회차 실행).
- 정보나루가 해외(깃허브) 서버의 연속 호출을 끊는 것인지, 일시 장애인지 — 며칠 실행 기록으로 본다.
