# 2026-10-18 — README 가독성 개편(server/ · relay/)

## 목적
심사위원과 다른 도시 담당자는 깃허브·공공 깃랩에서 안내 글을 휴대폰으로 먼저 열 수 있다. 좁은 화면에서 표 칸이 한두 글자씩 끊겨 읽기 어려웠던 `server/README.md`와 `relay/README.md`를, 11/8 동결 전에 루트 README(10/17)와 같은 기준으로 정리한다. 동작은 바꾸지 않는다.

## 도구
Claude(Claude Code, 모델 claude-opus-5-5) — 매일 점검(10/18) 중 작성

## 지시문 요지
1. 매일 점검 지침: 심사 가독성은 필수. README 첫 화면을 바꾸거나 글 전체를 고칠 때는 전·후를 먼저 보이고 담당자 승인 뒤 반영한다. 정직 고지는 지우거나 약하게 하지 않는다.
2. 담당자 승인(10/18): `server/README.md` 고침안(전·후 그림)을 반영하고, `relay/README.md`도 같은 방식으로 정리한다.

## 바뀐 것(저장소)
- `server/README.md` — 표 6개를 목록으로, 번호 차례 9절(무엇을 하나 · 바로 써 보기 · 모델에 붙이기 · 다섯 가지 모드 · 도구 계약 · 어디까지 진짜인가 · 다른 도시 · 다음 판과 범위 밖 · 문서 지도와 문의), 정직 고지를 첫 화면에, 파일 목록·도구 10종 시연·걸어온 길은 접이식.
- 바로잡은 사실(서버): `check_availability` 설명이 「관내 실시간(모의)」으로 적혀 있었으나, 실제로는 관내 16곳 소장·대출 상태(정보나루, 전일 기준)이고 demo 모드만 도서관리시스템 연결을 흉내 낸다. 매일 갱신 범위는 지금 시연 도서 5종(하루 81회 호출)으로 밝힘.
- `relay/README.md` — 표 2개를 목록으로, 번호 차례 8절(누가 어디로 묻나 · 원격 상담 비서 · 경로와 응답 · 배포와 걸리는 시간 · 실패해도 틀리게 말하지 않기 · 지키는 것 · 연결 · 점검), 커넥터 주소는 복사 단추가 붙는 코드 블록으로, 대조·규약 점검 내역과 응답 예는 접이식.
- 바로잡은 사실(중계): 참조 서버의 User-Agent 판(`chaekiji-mcp/0.3.4` → 지금 코드의 `0.3.5`), 정해 둔 경로에 `/mcp`(옛 글은 「넷뿐」), 원격 상담 비서는 claude.ai 출처도 받음, `/mcp`는 `worker.js`에만 있음, 배포 확인은 네 경로와 상담 1건, 대조 18건 내역(관내 상호대차·바로 이용이 각 2건 — 옛 글은 16건만 이름을 적었음). 첫 실측 기록(`consult_timing_2026-10-16.md`) 위치도 다시 적음.
- `CHANGELOG.md`·`server/CHANGELOG.md` 한 줄씩.

- 담당자: `server/README.md` 휴대폰 첫 화면 전·후 그림을 보고 승인, `relay/README.md`는 같은 방식으로 정리하도록 승인.

- 보안: 키·토큰·내부 주소 없음(공개 주소와 파일 경로만). 새 패키지 없음.

## 검증
- 깃허브식으로 그린 화면(marked GFM + github-markdown-css)을 휴대폰 390px·PC 1012px 폭에서 줄마다 글자 수를 셈. 1~3글자만 남는 줄(인라인 코드 글꼴 차이로 생기는 착시는 뺌) — `server/README.md` 휴대폰 78 → 0 · PC 9 → 0, 표 6 → 0, 휴대폰 길이 14,433 → 9,944px.
