## v0.3.5 — 2026. 10. 16. 모르면 「확인 불가」

- **틀린 안내 수정** — relay 모드에서 그 책의 소장 조회(중계 `/holdings`)만 실패하고 그 책이 8/18 픽스처에도 없으면, 픽스처의 빈 값이 「16곳 미소장」으로 읽혀 「책바다로 신청하세요」라는 틀린 안내가 나갔다(snapshot 모드의 목록 밖 도서도 같은 길). 이제 `naru._unknown`이 모든 관을 `unknown`으로, `LAST_META.unavailable`을 남기고, `check_availability`는 `status_unknown: true`로 전국 조회를 건너뛰며, `consult_request`는 갈래 **`check` 「소장 확인 불가(창구에서 조회)」**로 답한다 — 안내문에 조회일을 찍지 않고 창구 조회와 누리집 링크를 안내, 수령관 비치 규정도 「창구 확인」, 접수 메모는 「확인 불가」. 원격 판(`relay/mcp.js`)도 같게 고쳤다. 2026. 10. 16. 독립 검토에서 발견.
- 사서 모드 지시문 — `route: check`이면 있다·없다를 짐작하지 말고 창구 조회와 누리집 링크를 안내(3항), 판정 갈래에 「소장 확인 불가」(8항).
- (2차 검토) **서지 검색부터 끊긴 경우** — 예전에는 「도서 미확정 — 저자·출판사를 더 알려 주세요」로 이용자에게 되물었다(책이 없는 게 아니라 연결이 안 된 것인데). `naru.search`가 `unavailable: true`를 남기고, 상담 묶음은 갈래 `check`(책 없음)로 「지금 정보나루에 연결되지 않아 책을 찾지 못했습니다. 창구에서 도서관리시스템으로 찾아 드리겠습니다.」·접수 메모 「[조회 불가]」.
- (2차 검토) **예시 값으로 돌아가지 않음** — 정보나루가 끊겼을 때 예시 장면 값(지구 끝의 온실 「16곳 미소장」)으로 답하던 길을 막아, 실측 픽스처가 없는 책은 모두 「확인 불가」.
- (2차 검토) **제외 자료 규정을 「통과」로 두지 않음** — 정보나루 서지에는 자료 유형·신착 정보가 없는데 기본값(일반·신착 아님)으로 「통과」가 찍혔다. 시연 도서(픽스처) 밖의 책은 「자료 유형·신착 여부는 정보나루에 없어 창구에서 확인」으로 보류(회원 토큰이 있어도 같음). 접수 메모의 「규정 n건 통과」가 실제로 판정한 것만 센다.

## v0.3.4 — 2026. 10. 15. 「상담 비서」

창구·전화에서 사서가 지금 쓰는 상호대차 판정 도구를 서버에 얹었다. 도구 10종의 계약은 그대로다.

- **`consult_request`** 상담 묶음 도구 — 발화·수령관·언어 → `search_item` → `check_availability` → 규정 판정 → 갈래(바로 이용/관내 상호대차/예약/책바다) → 이용자 안내문(조회일·전일 기준 포함) → 접수 메모. 접수하지 않는다. 회원 토큰이 없으면 비치·제외자료 규정만 확정하고 한도 3종·연체·중복은 「창구 확인」으로 보류, 토큰이 있으면 7종 전부 판정.
- (10. 16.) **매일 갱신 첫 실측과 보강** — 깃허브 서버에서 정보나루 호출에 연결 거절·시간 초과가 섞여 나왔다. `naru._get`: 일시 장애 다시 시도(`NARU_RETRIES`, 갱신은 3번), 호출 간격(`NARU_PACE`, 갱신은 0.4초), https가 안 되면 매뉴얼의 http 주소로 넘어가 처음 통한 주소 기억(`NARU_BASE`로 고정 가능). `refresh_today.py`: 실패 도서 한 바퀴 더, 실행 기록 `lab/out/refresh_status.json`(도서별 성공·까닭, 키는 ***), 조회일은 한국 날짜. `refresh.yml`: 실패해도 실행 기록은 커밋하고 빨간 X로 알림, 도서 목록을 고쳐 올리면 바로 실행, 비밀 이름 `NARUKEY`도 받음.
- (10. 16.) **예시 값 정정** — `fixtures/holdings.json`의 지구 끝의 온실(관내 16곳 미소장)은 실측이 아닌 장면용 예시였다(10/16 실제 조회는 16곳 소장). `_examples`로 표시하고, 데모 모드 상담 안내문은 날짜 대신 「예시 데이터 — 이 책의 실제 소장·대출과 다를 수 있습니다」라고 밝힌다(시험 ㉖에 반영).
- (10. 16.) **코랩 2종 구동 노트북** `lab/colab_model2.ipynb` — 설치 없이 코랩에서 Ollama·엑사원 3.5 2.4B·라마 3.2 3B로 같은 문의 5건을 처리하고 기록표를 만든다. `hosts/ollama_host.py`: 호출 기록에 판정 갈래·데이터 출처·조회일·도구 시간·질문을 더하고, `--answers`로 질문마다 최종 답을 남긴다(기존 기록 칸은 그대로).
- (10. 16.) **원격 상담 비서** — 중계 서버의 `/mcp`(MCP Streamable HTTP)에서 같은 상담 묶음을 원격으로: claude.ai 커스텀 커넥터에 주소를 넣으면 설치 없이 쓴다. 도구 3종(`consult_request`·`search_item`·`check_availability`, 읽기 전용) + 프롬프트 `consult` + 사용 안내. 회원 토큰·접수 없음. 설정·픽스처·지시문은 `relay/build_mcp_data.py`가 이 폴더의 원본에서 옮기고(`--check`로 어긋남 시험), `relay/test_mcp_parity.py`가 이 서버(relay 모드)와 원격 판의 답을 14건 대조한다.
- (10. 16.) **중계 첫 배포와 보강** — 깃허브 액션 `deploy-relay.yml`로 Cloudflare Workers에 첫 배포(행정망에서 Cloudflare 화면이 막혀 있어서). `relay/worker.js`·`relay.py`: 정보나루 오류 문구(호출 한도 초과 등)를 「없음」으로 바꾸지 않고 502로, 실패 종류만(`detail`, 키·주소 없음), 주소마다 기다리는 한도와 통한 주소 기억, 요청 1건 외부 호출 45회 이하, 응답에 `via`. `naru.py`: 중계를 부를 때 이름을 밝히고(`User-Agent: chaekiji-mcp/0.3.4` — 파이썬 기본 이름은 Cloudflare가 403으로 막는 일이 있다), 중계의 실패 종류를 오류 문구에 싣는다(종전처럼 픽스처로 떨어짐), 중계 대기 8 → 20초(첫 확인에서 `/holdings` 약 9초). 부천 설정 `relay_url`에 배포 주소(`https://chaekiji-relay.altarry2.workers.dev`). 중계 점검 15 → 19건.
- (10. 16.) 안내문 끝 **공식 누리집 링크** — 설정 `official_search_url`(`{title}`/`{isbn13}` 틀)을 채워 그 책의 자료검색 화면으로. 접수는 이용자가 로그인해 직접(이 도구는 여전히 접수하지 않음). 관내에 없는 책·설정을 비운 도시에는 붙지 않는다. 출력 키 `official_link`.
- **MCP 프롬프트 `consult`** — 사서 모드 지시문을 서버가 갖는다(`prompts/상담비서-지시문.md`). 개인정보 입력 금지, 접수는 사서가, 조회일 유지, 이용자 언어 번역 규칙.
- **`CHAEKIJI_MODE=relay | auto`** — 중계(`relay/`)를 거쳐 키 없이 오늘 데이터. `auto`는 중계가 살아 있으면 relay, 아니면 demo(심사 기본값). 중계가 도중에 죽으면 그 호출만 픽스처로 떨어지고 근거 문구에 남는다. 설정 `relay_url` 또는 환경변수 `CHAEKIJI_RELAY`.
- 정보나루 커넥터 — 발화에서 요청 말투를 걷어내는 `clean_title`, 어느 모드든 `LAST_META.asof`(조회일), relay 모드의 서지 검색(픽스처 5종 우선).
- **매일 갱신** — `lab/refresh_today.py`(픽스처 5종 + `lab/refresh_list.txt`, `--max-calls`, `--demo`)가 `fixtures/holdings-today.json`·`../data/holdings-today.json`을 쓰고, 깃허브 액션 `refresh.yml`이 새벽 05:30(KST)에 돌려 커밋한다(키는 Secrets `NARU_KEY`에만). 서버는 `snapshot` 모드(또는 `auto`)로 읽고, relay 모드에서도 스냅샷에 있는 책은 중계를 부르지 않는다. 2일 넘은 스냅샷은 무시.

## v0.3.1 — 2026. 9. 27. (실험실 판)

도구 계약(10종)은 v0.3 그대로. AI 정부 실험실 과제로 세 가지를 추가:

- 관내 소장·대출을 정보나루로 조회하는 커넥터(`CHAEKIJI_LOCAL_SOURCE=naru`, 전일 기준)와 호출 계측
- 신청·위임 이력의 영속 저장(`CHAEKIJI_STORE`, SQLite 시험 구현)
- 대행 실행의 감사 기록(`CHAEKIJI_AUDIT`, 해시 사슬 JSONL)

셋 다 환경변수로만 켜지며, 끄면 v0.3과 같다. 실험실 스크립트·기록지·설계 문서는
`lab/`·`docs/`·`prompts/`에 있다.
