## 공개 모델 2종 — 엑사원 3.5 2.4B · 라마 3.2 3B (2026. 10. 18.)

코랩 노트북(`server/lab/colab_model2.ipynb`)의 코드 칸을 깃허브 액션(CPU 4코어, GPU 없음)에서 그대로 돌렸습니다. 담당자의 행정망 PC에서 코랩이 열리지 않아서입니다. 같은 서버·같은 지시문·같은 문의 5건이며, 모델에게는 상담 도구(`consult_request`) 하나만 보입니다. 실행 도구는 가지 `tools/model2`에 있습니다.

| 차례 | 기록 |
|---|---|
| 1 (13:12) | 노트북 실행이 중간에 실패해 원 기록 8건만 남음(기록표 없음). 여기서 찾은 결함을 고친 뒤 다시 돌림 |
| 2 (14:12) | [기록표](model2_record_actions_2026-10-18_1412.md) — 두 모델 판정이 같은 문의 2/5, 엑사원이 3건을 도구의 결과 없이 답함 |
| 3 (14:25) | [기록표](model2_record_actions_2026-10-18_1425.md) — 같은 문의 4/5, 라마가 1건을 도구의 결과 없이 답함 |
| 4 (14:46) | [기록표](model2_record_actions_2026-10-18_1446.md) — 같은 문의 5/5 |

- 기록표가 남은 세 차례에서 두 모델이 모두 도구의 결과를 받은 문의 11건은 판정이 모두 같았습니다.
- 도구의 결과 없이 답한 4건은 소장 사실이 틀린 답 2건, 판정이 틀린 답 1건, 답을 미룬 1건이었습니다. 판정을 모델에 맡기지 않는 까닭입니다.
- 판정이 같아도 작은 모델은 안내문을 옮기며 도서관 이름을 틀리거나(엑사원), 베트남어 문의에 한국어로 답했습니다(두 모델). 기록표의 「답 원문」을 펼치면 그대로 보입니다.
- 원 기록: `host_log_actions_…`(도구 호출) · `host_answers_actions_…`(최종 답). 1차는 원 기록만 있습니다.
- 이 기록은 처음에 가지 `tools/model2`에 쌓였고, 2026. 10. 26. 제출 저장소(main)로 옮겼습니다. 내용은 바꾸지 않았습니다.
