# 책이지 MCP 참조 서버 (chaekiji-mcp)

> **말 한마디로 시작한 도서 상호대차를 끝까지 대신 하는 도서관 AI 에이전트의 실행 계층.**
> 답을 돌려주는 챗봇이 아니라, 소장 확인 → 규정 판정 → 신청 → 추적 → 취소까지 실제 절차를 수행하는
> **표준 도구 10종**을 MCP(Model Context Protocol) 서버로 구현한 참조 구현입니다.

| 판 | 시험 | 의존성 | 모델 | 라이선스 | 만든 곳 |
|---|---|---|---|---|---|
| **v0.3.3** (2026. 10. 13.) | **47건 통과** — 적합성 33 + 실험실 점검 14 | Python 3.9+ · PyYAML 하나 | **비종속** — MCP 표준, 호스트를 바꿔 끼움 | MIT | 부천시립도서관 상동도서관 · 행정안전부 「AI 정부 실험실」 등록 과제 |

이 폴더(`server/`)는 통합 저장소 **chaekiji**의 실행 계층입니다. 시민용 화면(시연 웹)은 저장소 루트에 있고, 이 둘이 합쳐져 하나의 제안이 됩니다 — 전체 그림은 [루트 README](../README.md).
(2026. 10. 13. 통합 — 종전 단독 저장소 `chaekiji-mcp`는 보관(읽기 전용) 상태로 남겨 두었습니다.)

## 60초 요약

- **문제.** 도서관 상호대차는 홈페이지 로그인부터 신청까지 화면 아홉 번을 거칩니다. 규정(한도·수령관 비치·연체·제외 자료)은 이용자가 머릿속으로 맞춰야 하고, 어르신·시각장애인·다문화 주민은 그 앞에서 멈춥니다.
- **해법.** 이용자는 "나미야 잡화점 빌리고 싶어요" 한마디만 합니다. 모델은 **말을 알아듣는 일**만 하고, 그 뒤의 조회·판정·신청은 **규칙으로 짜인 도구**가 합니다. 그래서 모델을 바꿔도 결과가 같고, 비용이 거의 들지 않습니다.
- **이 저장소가 증명하는 것.** 도구 10종의 **계약**(이름·입력·출력·거부 조건)이 어느 모델, 어느 도서관에서도 같다는 것. 다른 도시는 설정 파일 하나를 새로 쓰면 되고, 다른 모델은 호스트 설정만 바꾸면 됩니다.
- **지금 상태.** 시연·검증 단계입니다. 신청은 모의 커넥터에 접수되며 **실제 도서관리시스템에는 들어가지 않습니다**(아래 「무엇이 진짜이고 무엇이 모의인가」).

## 바로 써 보기 — 2분

처음 받은 PC에서 이것 하나면 됩니다(demo 모드 · 네트워크·인증키 불필요):

    Windows:      run.bat
    macOS·Linux:  sh run.sh

의존성 설치(PyYAML) → 적합성 시험 33건 → 실험실 점검 14건을 차례로 돌리고 「준비 완료」를 찍습니다.

MCP 클라이언트에 연결하려면 호스트의 설정 파일에 서버 한 줄을 등록합니다 — 명령 `python3`(Windows는 `python`), 인자 `server.py`. 예시 파일:
클로드 데스크톱 `claude_desktop_config.example.json` · Codex CLI `lab/codex_config.example.toml` · VS Code `lab/vscode_mcp.example.json` · 로컬 공개 모델(Ollama) `docs/모델2종-구동.md`.

등록 뒤 대화창에 이렇게 말해 봅니다.

    나미야 잡화점 부천에서 빌릴 수 있어? 토큰은 tok_kimsj, 상동 수령
    → search_item → check_availability → check_policy → request_service 가 차례로 호출된다
    방금 신청 어떻게 됐어?        → track_request
    취소해줘                     → cancel_request

실계(live) 모드 — 인증키는 환경변수로만(코드·설정 파일에 쓰지 않습니다):

    read -s NARU_KEY; export NARU_KEY
    CHAEKIJI_MODE=live CHAEKIJI_LOCAL_SOURCE=naru python3 server.py

다른 도시 설정으로: `CHAEKIJI_CONFIG=config/example-city.yaml python3 server.py`

## 표준 도구 10종 (조회 3 + 판정·실행 7)

| 도구 | 역할 |
|---|---|
| `search_item` | 일상어 발화 → ISBN 확정(근거 포함) |
| `check_availability` | 관내 실시간(모의) → 없으면 전국(정보나루 · 전일 기준) |
| `find_alternative` | 점자·오디오북 대체자료 → 책나래 분기 근거 |
| `check_policy` | 규정 7종 판정 — 수령관 비치 · 한도 3종 · 연체 정지 · 제외 자료 · 중복 신청 |
| `request_service` | 신청 실행 — 즉시 확인 또는 사전 위임, **실행 직전 재판정**, `client_ref` 멱등(이중 신청 방지) |
| `track_request` | [v0.3] 접수→확보→이송→도착(보관기한)→대출/실패/취소 추적, 본인 한정 |
| `cancel_request` | [v0.3] 본인 취소 — 즉시 한도 복원 |
| `notify_user` | 선호 채널(문자·음성전화) 알림 |
| `suggest_items` | [확장] 이달의 추천(운영: AI 책큐·정보나루 커넥터) |
| `manage_mandate` | [확장] 사전 위임장(책이지 패스) create/status/revoke — 동의 일시·고지문 판·해지 기록 보존 |

안전 원칙 한 줄: **확인 없이는 실행하지 않는다.** 실행 권한은 그 자리의 확인(`confirmed_by_user`) 또는 범위가 명시된 사전 위임(`mandate_id`) 둘 중 하나이고, 어느 쪽이든 실행 직전에 규정을 다시 판정합니다. 위임 범위(무료 경로만 · 주기당 권수)를 벗어나면 스스로 멈추고 사람에게 돌립니다.

## 무엇이 진짜이고 무엇이 모의인가 (정직 고지)

| 구성요소 | 상태 |
|---|---|
| MCP 서버 (stdio JSON-RPC, 도구 10종) | **진짜** — 표준 클라이언트 연결 가능 |
| 규정 판정 엔진 + 설정(YAML) 분리 | **진짜** — 시험으로 검증(같은 코드·같은 회원이 가상시 규정으로는 차단됨) |
| 신청 생애주기 · 한도 복원 · 멱등성 | **진짜** — 로직 구현·시험 검증(상태 전이는 `_sim` 데모 훅으로 재현) |
| 정보나루 커넥터 | demo: 2026. 8. 18. 실측 픽스처 / live: 실제 API 호출(인증키 필요) · 대출 가능 여부는 **조회일 전일 기준** |
| 도서관리시스템(알파스) 커넥터 | **모의** — 함수 7개가 곧 벤더 연동 명세(`connectors/alpas_stub.py` 주석) |
| 회원 데이터 | 가상 인물(김○자·박○수) |
| 신착·비도서 제외, 보관기한 값 | **예시 규정** — 기관 확정 규정으로 교체하는 자리 |
| [v0.3.1] 영속 저장 · 감사 기록 | **시험 구현** — SQLite · 해시 사슬 JSONL. 암호화·운영 DB·기관 감사 시스템 연계는 설계 문서까지(`docs/`) |

`_sim`(상태 전이 훅)은 데모·시험 전용이며 `tools/list`에 노출되지 않습니다. 운영에서 상태를 바꾸는 주체는 도서관리시스템뿐입니다.

## 확산 절차 — 이 저장소가 주장하는 바

1. 도서관 코드표·규정 숫자를 담은 `config/<도시>.yaml` 작성 — 반나절
2. 도서관리시스템이 알파스면 `alpas_stub.py`의 함수 7개를 벤더 API로 채운 커넥터를 재사용
3. 다른 시스템(KOLAS 등)이면 같은 함수 7개짜리 커넥터를 1회 개발 → 전국 공유
4. `tests/run_scenarios.py` 통과 = 책이지 에이전트와 호환 보장

확산의 산수: 도시 수만큼이 아니라 **도서관리시스템 종류 수만큼**만 개발하면 됩니다. 모델을 바꿔도 ③④층은 그대로입니다.

## 다음 판 v0.4 — 예정

2026년 9월 지자체 통합도서관 다섯 곳의 공개 규정을 대조해 v0.3 계약과 어긋나는 다섯 가지(예약 분기 · 책바다는 안내만 · 미수령 제재 · 취소 시점 · 예상 수령일 계산)를 찾았고, 시연 웹에는 반영했으며 참조 서버는 다음 판의 몫입니다. 여기에 두 가지를 더합니다.

- **위임 범위 안 자동 재경로** — 소장관에서 확보에 실패하면, 활성 위임장이 있을 때만 다음 소장관에 자동 재신청하고 통지. 관내 소장관이 더 없으면(예약·책바다 = 범위 밖) 멈추고 사람에게 묻는다. 우회하는 것은 **재고**이지 규정이 아니다.
- **기억의 경계** — 이용자 설정과 위임장은 기억하되, 무엇을 읽었는지는 기억하지 않는다(시연 웹의 「기억 보기·지우기」와 짝).

계획 전문: [docs/ROADMAP-v0.4.md](docs/ROADMAP-v0.4.md) · 설정 초안: `config/bucheon.v0.4-draft.yaml`(【확인】 = 부천 규정으로 교체할 자리, v0.3 서버는 읽지 않음)

## 참조 구현이 다루지 않는 것 — 실전 전환 시 보완 항목

이 저장소는 표준 도구 계층의 **계약**을 증명합니다. 다음은 구축 단계의 몫이며 의도적으로 범위 밖에 두었습니다.

- 실제 회원 인증 — 도서관 홈페이지/SSO 연동, 토큰 발급·만료·회전(`vault.py`는 시연용 고정 토큰)
- 알림 실발송 — 알림톡·SMS 게이트웨이 연계(`send_notice`는 큐 적재까지)
- 저장 계층 — 위임장·신청 이력의 운영 DB 영속화와 암호화(v0.3.1은 SQLite 시험 구현까지)
- 성능·가용성 — 도서관리시스템 야간 배치 시간대 부하, 호출 제한, 장애 대비
- 감사 로그 — 기관 감사 시스템 연계(v0.3.1은 해시 사슬 JSONL까지)
- 운영 규정 확정 — 신착 제외 기간·제외 유형·보관기한 등 예시값의 기관 확정
