# 변경 기록 (chaekiji-mcp)

## v0.3.4 — 2026. 10. 15. 「상담 비서」

창구·전화에서 사서가 지금 쓰는 상호대차 판정 도구를 서버에 얹었다. 도구 10종의 계약은 그대로다.

- **`consult_request`** 상담 묶음 도구 — 발화·수령관·언어 → `search_item` → `check_availability` → 규정 판정 → 갈래(바로 이용/관내 상호대차/예약/책바다) → 이용자 안내문(조회일·전일 기준 포함) → 접수 메모. 접수하지 않는다. 회원 토큰이 없으면 비치·제외자료 규정만 확정하고 한도 3종·연체·중복은 「창구 확인」으로 보류, 토큰이 있으면 7종 전부 판정.
- (10. 16.) **매일 갱신 첫 실측과 보강** — 깃허브 서버에서 정보나루 호출에 연결 거절·시간 초과가 섞여 나왔다. `naru._get`: 일시 장애 다시 시도(`NARU_RETRIES`, 갱신은 3번), 호출 간격(`NARU_PACE`, 갱신은 0.4초), https가 안 되면 매뉴얼의 http 주소로 넘어가 처음 통한 주소 기억(`NARU_BASE`로 고정 가능). `refresh_today.py`: 실패 도서 한 바퀴 더, 실행 기록 `lab/out/refresh_status.json`(도서별 성공·까닭, 키는 ***), 조회일은 한국 날짜. `refresh.yml`: 실패해도 실행 기록은 커밋하고 빨간 X로 알림, 도서 목록을 고쳐 올리면 바로 실행, 비밀 이름 `NARUKEY`도 받음.
- (10. 16.) **예시 값 정정** — `fixtures/holdings.json`의 지구 끝의 온실(관내 16곳 미소장)은 실측이 아닌 장면용 예시였다(10/16 실제 조회는 16곳 소장). `_examples`로 표시하고, 데모 모드 상담 안내문은 날짜 대신 「예시 데이터 — 이 책의 실제 소장·대출과 다를 수 있습니다」라고 밝힌다(시험 ㉖에 반영).
- (10. 16.) 안내문 끝 **공식 누리집 링크** — 설정 `official_search_url`(`{title}`/`{isbn13}` 틀)을 채워 그 책의 자료검색 화면으로. 접수는 이용자가 로그인해 직접(이 도구는 여전히 접수하지 않음). 관내에 없는 책·설정을 비운 도시에는 붙지 않는다. 출력 키 `official_link`.
- **MCP 프롬프트 `consult`** — 사서 모드 지시문을 서버가 갖는다(`prompts/상담비서-지시문.md`). 개인정보 입력 금지, 접수는 사서가, 조회일 유지, 이용자 언어 번역 규칙.
- **`CHAEKIJI_MODE=relay | auto`** — 중계(`relay/`)를 거쳐 키 없이 오늘 데이터. `auto`는 중계가 살아 있으면 relay, 아니면 demo(심사 기본값). 중계가 도중에 죽으면 그 호출만 픽스처로 떨어지고 근거 문구에 남는다. 설정 `relay_url` 또는 환경변수 `CHAEKIJI_RELAY`.
- 정보나루 커넥터 — 발화에서 요청 말투를 걷어내는 `clean_title`, 어느 모드든 `LAST_META.asof`(조회일), relay 모드의 서지 검색(픽스처 5종 우선).
- **매일 갱신** — `lab/refresh_today.py`(픽스처 5종 + `lab/refresh_list.txt`, `--max-calls`, `--demo`)가 `fixtures/holdings-today.json`·`../data/holdings-today.json`을 쓰고, 깃허브 액션 `refresh.yml`이 새벽 05:30(KST)에 돌려 커밋한다(키는 Secrets `NARU_KEY`에만). 서버는 `snapshot` 모드(또는 `auto`)로 읽고, relay 모드에서도 스냅샷에 있는 책은 중계를 부르지 않는다. 2일 넘은 스냅샷은 무시.
- **`hosts/ollama_host.py`** — 로컬 공개 모델(Ollama) 호스트. 표준 라이브러리만, Ollama 도구 호출(native)과 「JSON 한 덩어리」(json) 두 방식, 자동 전환, 호출 기록 JSONL.
- 중계(`relay/`) — `/search`(서지)·`/nation`(광역 소장 수) 경로 추가, 호출 상한 60회/10분, `test_worker.mjs`(모의 정보나루) 14건.
- 시험 — 적합성 33 → **48건**(상담 묶음 10 + 프롬프트 2 + 설정 교체 2 추가) · `tests/run_relay.py` 14건(중계 9 + 스냅샷 5) · `tests/run_host.py` 6건 · 실험실 14건 = **82건**. `run.bat`/`run.sh`·CI에 반영.
- 문서 — README 「상담 비서」 절, `docs/모델2종-구동.md`(엑사원·라마·젬마, 기록표), 「확산 절차」 절 제목을 「다른 도시에 옮기면」으로.
- 동작 변화 없음(기존 도구 10종·규정·생애주기 동일). v0.4 로드맵은 그대로 다음 판.

새 판이 위로 온다. 도구 계약(표준 도구 10종)의 변화는 굵게 표시한다.

## v0.3.1 — 2026. 9. 27. (실험실 판)

도구 계약(10종)은 v0.3 그대로. AI 정부 실험실 과제로 세 가지를 추가:

- 관내 소장·대출을 정보나루로 조회하는 커넥터(`CHAEKIJI_LOCAL_SOURCE=naru`, 전일 기준)와 호출 계측
- 신청·위임 이력의 영속 저장(`CHAEKIJI_STORE`, SQLite 시험 구현)
- 대행 실행의 감사 기록(`CHAEKIJI_AUDIT`, 해시 사슬 JSONL)

셋 다 환경변수로만 켜지며, 끄면 v0.3과 같다. 실험실 스크립트·기록지·설계 문서는
`lab/`·`docs/`·`prompts/`에 있다.
