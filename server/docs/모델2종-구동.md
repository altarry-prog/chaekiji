# 모델 2종 구동 — 모델 비종속 입증 절차 (v0.3.2)

이 서버는 MCP(Model Context Protocol) 표준의 stdio 방식이라, 어느 호스트에 연결하든
등록 내용은 똑같다: 명령 `python3`(Windows는 `python`), 인자 `server.py` 하나.
그래서 "모델을 바꿔도 같은 도구가 그대로 돈다"는 것을 호스트 2종에서 같은 시나리오로
실측해 보이면, 특정 모델(LLM)에 묶이지 않는 구조가 입증된다.

## 호스트 A — 클로드 데스크톱 (상용 모델)

1. `claude_desktop_config.example.json`의 내용대로 설정 파일에 서버를 등록하고 재시작한다.
2. 대화창에 시나리오 발화를 넣는다:
   「나미야 잡화점 부천에서 빌릴 수 있어? 토큰은 tok_kimsj, 상동 수령」
3. search_item → check_availability → check_policy → request_service 호출이 일어나는
   화면을 확인하고, 이어서 「방금 신청 어떻게 됐어?」(track_request) ·
   「취소해줘」(cancel_request)까지 생애주기를 확인한다.

## 호스트 B — 로컬 공개 모델 (행정안전부 AI 공통기반 지원 계열)

공통기반이 지원(예정 포함)하는 공개 모델 가운데 젬마(Gemma)·라마(Llama)는
Ollama로 개인 PC에서 돌릴 수 있다. GPU 없는 사무용 PC에서도 소형 모델은
느리지만 동작한다(속도는 입증 대상이 아니다 — 같은 도구가 호출되는지가 핵심).

1. Ollama를 설치하고 소형 공개 모델을 받는다. 모델 이름·태그는 설치 시점의
   Ollama 목록을 따른다【구동 시점에 확정해 기록】.
2. MCP를 지원하는 로컬 호스트를 하나 고른다. 후보:
   - 공공 GitLab 공개 과제 `ollama-mcp-host`(서울 광진구 류승인, MIT) —
     로컬 Ollama로 여러 MCP 서버를 함께 돌리는 호스트. 사용 시 출처를 구동안내서에 밝힌다.
   - VS Code의 MCP 설정(`lab/vscode_mcp.example.json`) + 로컬 모델 확장 조합.
3. 그 호스트의 서버 등록 양식(각 저장소 README를 따름)에 chaekiji-mcp를
   `python3 server.py`로 등록한다 — 호스트 A와 등록 내용이 같다는 점이 요지.
4. 호스트 A와 **같은 시나리오 발화**를 넣고, 같은 도구 호출이 일어나는 화면을 확인한다.
