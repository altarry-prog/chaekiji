## 60초 요약

- **문제.** 상호대차 한 번에 홈페이지 로그인부터 신청까지 화면 아홉 번. 한도·수령관 비치·연체·제외 자료 같은 규정은 이용자가 머릿속으로 맞춰야 하고, 어르신·시각장애인·다문화 주민은 그 앞에서 멈춥니다.
- **해법.** 이용자는 "나미야 잡화점 빌리고 싶어요" 한마디. 모델은 **말을 알아듣는 일**만 하고, 조회·판정·신청은 **규칙으로 짜인 도구 10종**이 합니다. 그래서 모델을 바꿔도 결과가 같고 비용이 거의 들지 않습니다.
- **이 저장소가 증명하는 것.** ① 시민이 실제로 쓸 수 있는 화면(음성·10개 언어·큰글자·전화)과 ② 어느 도서관·어느 모델에서도 같은 **도구 계약**. 다른 도시는 설정 파일 하나, 다른 모델은 호스트 설정만 바꾸면 됩니다.
- **지금 상태.** 시연·검증 단계. 신청은 모의 커넥터에 접수되고 실제 도서관리시스템에는 들어가지 않습니다(아래 「무엇이 진짜이고 무엇이 모의인가」).

## 바로 돌려보기 — 참조 서버 (2분)

처음 받은 PC에서 이것 하나면 됩니다(demo 모드 · 네트워크·인증키 불필요):

    Windows:      server\run.bat
    macOS·Linux:  sh server/run.sh

의존성 설치(PyYAML 하나) → 적합성 시험 33건 → 실험실 점검 14건을 차례로 돌리고 「준비 완료」를 찍습니다.

## 무엇이 진짜이고 무엇이 모의인가 (정직 고지)

| 구성요소 | 상태 |
|---|---|
| 화면·음성·다국어·판정 흐름 | **진짜** — 브라우저에서 전부 동작 |
| MCP 서버(stdio JSON-RPC, 도구 10종) · 규정 엔진 · 설정 분리 · 신청 생애주기 | **진짜** — 표준 클라이언트 연결 가능, 시험 47건으로 검증 |
| 소장·대출 데이터 | **실측값 고정 탑재** — 2026. 8. 18. 정보나루 조회 64건 · 대출 가능 여부는 **조회일 전일 기준** (서버 live 모드는 실제 호출, 인증키는 환경변수로만) |
| 상호대차 신청 | **시연** — 실제 접수되지 않음. 도서관리시스템 커넥터는 **모의**이며, 그 함수 7개가 곧 벤더 연동 명세 |
| 책이지 패스(사전 위임) | **위임 흐름·범위 판정은 진짜, 위임장 보존·통지는 시연** |
| 전화 한 통 모드 | **대화 흐름은 진짜, 전화망은 시연** — 실제 전화는 걸리지 않음 |
| 등록된 기기(패스키) · 바코드 · 기기 내 음성 인식 · WebMCP | **지원 기기·브라우저에서만** — 패스키는 기기 안에서는 진짜, 서버 검증은 없음(기본 꺼짐) |
| 외국어 음성 인식 | **기기·브라우저의 인식 언어 범위에 달림** — 미지원 언어는 글자 입력으로 안내, 번역은 시연 웹이 하지 않음 |
| 회원 데이터 · 신착·비도서 제외·보관기한 값 | 가상 인물 · **예시 규정**(기관 확정 규정으로 교체하는 자리) |

항목별 긴 설명은 [docs/시연웹-기능-상세.md](docs/시연웹-기능-상세.md)와 [server/README.md](server/README.md)의 같은 절에 있습니다.

## 확산의 산수

다른 도시는 도서관 코드와 규정 숫자를 담은 `server/config/<도시>.yaml` 하나를 새로 쓰면 되고(반나절), 도서관리시스템이 같으면 커넥터를 재사용하고 다르면 함수 7개짜리 커넥터를 한 번만 만들어 전국이 공유합니다. 즉 **도시 수만큼이 아니라 도서관리시스템 종류 수만큼**만 개발하면 됩니다. 모델을 바꿔도 도구·커넥터 층은 그대로입니다. 화면도 바꿔 끼울 수 있습니다 — 도서관 홈페이지든 키오스크든 같은 도구를 부르면 됩니다.
