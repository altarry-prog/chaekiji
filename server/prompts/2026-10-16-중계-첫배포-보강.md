# 2026-10-16 — 중계 첫 배포와 보강 (Claude 생성, 사람 확인)

## 목적
행정망 PC에서는 Cloudflare 화면이 열리지 않는다. 그래서 중계(relay/worker.js)를 깃허브 액션 `deploy-relay.yml`로 올리고 있다. 담당자는 휴대전화로 Cloudflare API 토큰을 만들어 깃허브 비밀값에 직접 넣었다. 토큰과 정보나루 키는 채팅·코드·파일 어디에도 없다.

## 일어난 일(실측)
1. 1·2회차는 실패했다. 계정을 찾지 못했고 인증 오류가 났다. 토큰이 「Cloudflare Stream 및 Images 읽기 및 쓰기」 템플릿으로 만들어져 Workers 권한이 없었기 때문이다. 담당자가 「Cloudflare Workers 편집」 템플릿으로 다시 만들었다. 계정 ID는 비밀값이 아니어서 `wrangler.toml`에 적었다.
2. 3회차(17:34)는 배포에 성공했다. 주소는 `https://chaekiji-relay.altarry2.workers.dev`다.
   - 그런데 깃허브 서버에서 `/health`를 물으면 응답 본문 없이 실패했고, `/holdings`는 403이었다.
   - 중계 코드는 허용 밖 출처(Origin)일 때만 403을 낸다. 확인 요청에는 Origin이 없었으므로, 403은 Cloudflare 쪽에서 낸 것으로 추정한다. 파이썬 기본 이름(Python-urllib)을 막는 Cloudflare 검사로 보이며, 4회차 기록으로 확인한다.
3. 같은 시각 웹 가져오기 도구로 물었을 때 결과는 이렇다.
   - `/health`: `{"ok":true,"keyed":true,"region":"31050"}`. 키가 들어갔다.
   - `/holdings`: 오류. 중계가 실패 까닭을 남기지 않아 원인을 알 수 없었다.

## 지시 요지와 바꾼 것
지시 요지는 「너가 알아서 다해줘」였다. 행정망 제약 안에서 담당자 손이 가지 않게 했다.

`worker.js`에서 바꾼 것은 다음과 같다.
- 주소마다 기다리는 한도를 두었다. https는 2.5초, http는 12초다.
- 한 번 통한 주소를 기억했다가 다음에 먼저 쓴다.
- 요청 1건의 외부 호출을 45회 안으로 묶었다. 무료 요금제 상한은 50회다.
- 정보나루가 오류 문구를 주면(호출 한도 초과 등) 「없음」으로 바꾸지 않고 오류로 낸다. 16관이 모두 미소장처럼 보이는 일을 막기 위해서다.
- 실패하면 실패 종류(detail)만 돌려준다. 키와 주소는 지운다.
- 응답에 통한 주소 종류(`via`)를 남긴다.

`relay.py`(파이썬 판)는 정보나루 오류 문구와 실패 종류를 `worker.js`와 같은 규칙으로 처리하게 했다.

`deploy-relay.yml`에서 바꾼 것은 다음과 같다.
- 확인 요청이 이름을 밝히고 묻는다(User-Agent).
- 파이썬 기본 이름으로 물은 결과는 따로 적는다.
- 웹 출처(CORS) 허용과 `/holdings`·`/search`·`/nation` 결과를 기록한다. 실패하면 상태 번호와 실패 종류를 남긴다.

`server/connectors/naru.py`에서 바꾼 것은 다음과 같다.
- 중계를 부를 때 이름을 밝힌다(`chaekiji-mcp/0.3.4`).
- 중계가 준 실패 종류를 오류 문구에 싣는다. 이 오류는 원래대로 픽스처로 떨어진다.

## 검증
- 중계 점검 15건에 4건을 더해 19건이 통과했다.
  - 통한 주소 기록
  - 멈춘 주소를 끊고 다른 주소로 넘어가기
  - 정보나루 오류 문구가 오면 502로 내고 「없음」으로 바꾸지 않기
  - 상류 장애 때 외부 호출 45회 이하, 응답에 키·주소 없음
- `relay.py`는 따로 확인했다. 한도 초과 문구, 연결 거절과 503, 정상 응답 세 경우를 모의로 넣었고, 키가 가려지는 것도 보았다.
- 확인 단계 스크립트를 모의 중계로 시험했다. 기본 이름은 403이고 밝힌 이름은 200인 경우, CORS 헤더, 502 실패 종류 기록을 보았다.
- 시험 82건(적합성 48, 실험실 14, 중계 모드 14, 호스트 6)이 통과했다.
