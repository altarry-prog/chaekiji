# 알림 발송 경로 설계: notify_user의 운영 연결

작성 2026. 9. 27. · 실험실 이용 신청서의 「이용기간 중점 과제」 중 하나(알림 발송 경로 설계). 시험 구현은 큐 적재까지(`alpas_stub.send_notice`), 실제 발송은 없음.

## 1. 지금(v0.3.1)

- `notify_user(user, event, message)` → 회원의 선호 채널(모의: sms / voice_call)을 고르고 → 모의 발송함(`_outbox`)에 넣는다. 발송 결과는 `{"queued": true, "channel": ...}`.
- 감사 기록에는 채널만 남고 문구는 남지 않는다.

## 2. 이벤트와 채널

| 이벤트(event) | 언제 | 기본 채널 | 문구 요지 |
|---|---|---|---|
| `accepted` | 접수 직후 | 알림톡 → SMS 대체 | 접수번호·예상 수령일·수령관 |
| `confirmed` / `in_transit` | 소장관 확보·이송 | (선택) | 진행 상황 |
| `arrival` | 도착 | 알림톡/SMS + 음성전화(선호 시) | 보관기한, 미수령 시 자동 취소·제한 안내 |
| `remind_before_due` | 보관 마감 하루 전 | 알림톡/SMS | 남은 기한 |
| `ill_failed` | 실패(서가 부재·경합) | 알림톡/SMS | 사유, 대체자료·재신청 안내 |
| `canceled` | 이용자·시스템 취소 | 알림톡/SMS | 사유, 한도 복원 |
| `mandate_executed` | 사전 위임으로 자동 접수 | **매회** 알림(위임 조건) | 무엇을 접수했는지, 해지 방법 |
| `mandate_paused` | 미수령 1회로 위임 일시정지(v0.4) | 알림톡/SMS | 재개 방법 |

채널 우선순위: 이용자 선호 → 기관 기본(알림톡) → 실패 시 SMS 대체 → 음성전화(TTS)는 선호로 등록한 이용자만(시각장애·고령 이용자용).

## 3. 경로

```
책이지 도구(notify_user) → 알림 큐(저장 계층, 상태: queued/sent/failed)
   → 발송 워커 → ① 카카오 알림톡(기관 채널·템플릿 사전 승인)  ② SMS/LMS(기관 문자 게이트웨이)
                 ③ 음성전화(TTS ARS 사업자)  ④ 앱 푸시(시연 웹 PWA — 선택)
   → 결과 회신(sent/failed/no_answer) → 큐 갱신 → 감사 기록(채널·결과만)
```

- **연락처는 책이지가 갖지 않는다.** 발송 워커가 도서관리시스템(회원 원본)에서 발송 순간에만 조회하거나, 도서관리시스템의 기존 문자 발송 기능(벤더 함수 ⑤ `send_notice`)에 위탁한다. 후자가 개인정보 최소화에 유리하고 현행 도착 문자와 같은 경로라 권장.
- 재시도: 실패 시 10분 간격 3회 → SMS 대체 → 그래도 실패면 사서 확인 목록.
- 발송 시간: 08\~20시(야간 보류), 음성전화는 09\~18시.
- 템플릿: 알림톡은 사전 심사 필요 → 이벤트별 문안을 미리 등록(【확인】 카카오 비즈니스 채널 보유 여부).

## 4. 비용·계약(【확인】)

| 항목 | 확인할 것 |
|---|---|
| 알림톡·SMS 단가와 월 예상 건수 | 기관 문자 발송 계약(현행 도착 문자 단가) |
| 음성전화(TTS ARS) | 사업자·건당 요금, 시각장애 이용자 수 |
| 도서관리시스템 위탁 가능 여부 | 벤더 함수 ⑤ 지원 여부·API 유무(본부 정보팀 문의) |

## 5. 시험 구현에서 운영으로 가는 최소 변경

1. `alpas_stub.send_notice` → 벤더 커넥터(문자 발송 위탁) 또는 기관 게이트웨이 호출로 교체
2. 알림 큐를 `store.py`의 표로 옮기고 상태(queued/sent/failed)와 재시도 횟수 추가
3. 이벤트별 문안 파일(`config/notices.yaml`)로 분리(지역 고유값 원칙과 같음)
