# 실측 기록

사람이 고치지 않은 원 기록입니다(직원 측정은 직원이 보낸 기록표의 숫자를 그대로 옮김). 대출 상태는 정보나루 조회일의 전일 기준이며, 책이지의 어떤 기록도 실제 접수로 이어지지 않았습니다.

## 공개 모델 2종: 엑사원 3.5 2.4B · 라마 3.2 3B (2026. 10. 18.)

코랩 노트북(`server/lab/colab_model2.ipynb`)의 코드 칸을 깃허브 액션(GPU 없음)에서 그대로 돌렸습니다. 담당자의 행정망 PC에서 코랩이 열리지 않아서입니다. 같은 지시문·같은 문의 5건입니다. 2~4차는 모델에게 상담 도구(`consult_request`) 하나만 보였고(CPU 4코어), 1차는 도구 11종이 모두 보였습니다(CPU 2코어). 실행 도구는 가지 `tools/model2`에 있습니다.

| 차례 | 기록 |
|---|---|
| 1&nbsp;(13:12) | 노트북 실행이 중간에 실패해 원 기록 8건만 남음(기록표 없음). 도구 11종이 다 보인 상태에서 엑사원은 찾기 도구만 부르고 대출 상태를 지어냄. 여기서 찾은 결함을 고친 뒤 다시 돌림(`server/prompts/2026-10-18-공개모델-첫실측-결함수정.md`) |

| 4&nbsp;(14:46) | [기록표](model2_record_actions_2026-10-18_1446.md): 같은 문의 5/5 |

- 기록표가 남은 세 차례에서 두 모델이 모두 도구의 결과를 받은 문의 11건은 판정이 모두 같았습니다.
- 도구의 결과 없이 답한 4건은 소장 사실이 틀린 답이 2건, 판정이 틀린 답이 1건, 답을 미룬 것이 1건이었습니다. 판정을 모델에 맡기지 않는 설계를 뒷받침합니다.
- 판정이 같아도 작은 모델은 안내문을 옮기며 도서관 이름이나 대출 상태를 틀리게 적었고(두 모델 모두), 베트남어 문의에는 기록된 여섯 번 모두 한국어로만 답했습니다. 기록표의 「답 원문」을 펼치면 그대로 보입니다.
- 차례마다 호스트를 고쳤으므로 같은 조건을 되풀이한 결과가 아닙니다(고칠 때마다 나아짐).
- 원 기록: `host_log_actions_…`(도구 호출) · `host_answers_actions_…`(최종 답). 1차는 원 기록만 있습니다.
- 이 기록은 처음에 가지 `tools/model2`에 쌓였고, 2026. 10. 26. 제출 저장소(main)로 옮겼습니다. 내용은 바꾸지 않았습니다.

## 신청 절차 직원 측정 (2026. 10. 27.)
