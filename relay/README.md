# relay/ — 정보나루 중계와 원격 상담 비서

**인증키를 숨긴 채 정보나루 실데이터를 쓰게 하는 얇은 층입니다.**

시연 웹(깃허브 페이지스)은 정적 페이지라 비밀값을 가질 수 없습니다. 그래서 키를 가진 작은 중계를 하나 두고, 시연 웹과 상담 비서는 중계에만 묻습니다. 같은 서버의 `/mcp` 경로는 claude.ai에 붙는 원격 상담 비서입니다.

- 중계(Cloudflare Workers 무료, 2026. 10. 16.~) — `https://chaekiji-relay.altarry2.workers.dev`
- 원격 상담 비서 — 같은 주소 끝에 `/mcp`
- 운영 점검 7/7 · 중계 점검 19건 · 원격 점검 30건 · 파이썬 판 대조 21건(2026. 10. 18.)

> **정직 고지** — 대출 상태는 조회일의 **전일 기준**입니다. 원격 상담 비서는 읽기와 판정만 하고 **접수하지 않습니다**. 인증키는 서버 비밀값에만 두고, 어디에도 내보내지 않습니다.

설계와 원칙은 [server/docs/정보나루-중계-설계.md](../server/docs/정보나루-중계-설계.md)에 있습니다.

## 1. 누가 어디로 묻나

- **시연 웹** — 책 한 권의 16관 소장·대출(`/holdings`)을 묻습니다.
- **claude.ai 커넥터** — 원격 상담 비서(`POST /mcp`)를 부릅니다.
- **참조 서버(relay 모드)** — 찾기·소장·전국(`/search`·`/holdings`·`/nation`)을 묻습니다.
- 중계가 없거나 답이 없으면 8. 18. 실측 자료로 돌아가고, 화면과 안내문에 그 사실을 밝힙니다.

**중계 없이 되는 길 — 매일 새벽 자료**

깃허브 액션(`refresh.yml`)이 정해 둔 도서의 조회분을 새벽마다 받아 `data/holdings-today.json`으로 커밋합니다. 시연 웹과 서버(auto 모드)는 이 파일을 먼저 읽습니다.

대출 상태는 어차피 전일 기준이라, 하루 한 번이면 신선도가 같습니다. 중계는 목록에 없는 책(상담 비서의 임의 문의)을 위한 것입니다.

**두 가지 판** — 비용은 둘 다 0원입니다.

- `worker.js` — Cloudflare Workers(무료)에서 24시간 돕니다. 깃허브 액션이 올리며, 원격 상담 비서(`/mcp`)는 이 판에만 있습니다.
- `relay.py` — 도서관 PC·실험실 VM용 파이썬 판(의존성 없음). 개발·검증용이며, 네 경로의 응답이 `worker.js`와 같습니다.

## 2. 원격 상담 비서 — claude.ai 커넥터

**왜** — 행정망 PC처럼 파이썬·설치형 앱을 쓸 수 없는 곳에서도, 인터넷 창의 claude.ai만으로 상담 비서를 쓰게 하려고 만들었습니다. 심사위원도 설치 없이 1분이면 붙습니다.

**붙이는 법**

1. claude.ai에서 「사용자 정의 → 커넥터 → + 추가 → 커스텀 커넥터 추가」를 누릅니다.
2. 이름은 「책이지 상담 비서」로 적고, 아래 주소를 넣은 뒤 「계속」을 누릅니다.

   ```text
   https://chaekiji-relay.altarry2.workers.dev/mcp
   ```

3. 인증 방식은 「로그인 없음」을 고르고 「추가」를 누릅니다.
4. 새 대화의 「+ → 커넥터」에서 켜고, 이용자의 말을 그대로 적습니다.

   > 나미야 잡화점의 기적 빌리고 싶어요, 상동에서 받을게요

무료 요금제는 커스텀 커넥터를 1개까지 쓸 수 있고, 팀·기업 요금제는 소유자만 추가할 수 있습니다(claude.ai 도움말). 이 주소를 인터넷 창으로 열면 붙이는 법이 나옵니다.

**무엇을 하나** — 파이썬 참조 서버(`server/`)를 relay 모드로 띄운 것과 같습니다. 찾기, 관내 소장·대출, 규정 판정, 이용자 안내문, 접수 메모를 차례로 합니다. 관내 소장·대출은 오늘 새벽 자료를 먼저 쓰고, 없으면 정보나루를 그 자리에서 부릅니다.

- 도구 3종(모두 읽기 전용): `consult_request` · `search_item` · `check_availability`
- 프롬프트 `consult`(사서 모드 지시문)와 처음 연결할 때 주는 사용 안내
- **하지 않는 것** — 접수·취소·위임·알림, 회원 토큰(받으면 거절), 상태 저장(세션 없음). 개인정보를 받지 않습니다.
- 설정·자료·지시문은 `server/`의 원본을 옮겨 씁니다. 손으로 고치지 않으며, 어긋나면 시험이 실패합니다. 옮기는 도구는 `relay/build_mcp_data.py`입니다.

**두 판이 같은 답을 내는지** — `python3 relay/test_mcp_parity.py`가 같은 시나리오를 파이썬 판과 원격 판에 넣습니다. 판정·안내문·접수 메모·근거 문구·링크를 글자 단위로 대조합니다(18건).

## 3. 경로와 응답

날짜는 `YYYY-MM-DD`입니다.

- `GET /holdings?isbn=…` — 16관의 `ok`·`busy`·`none`과 조회일, 호출 수, 통한 주소 종류, 캐시 여부
- `GET /search?q=…` — 제목 부분일치 최대 5건(ISBN·서명·저자·출판사·연도). ISBN으로 물으면 서지 한 건을 줍니다.
- `GET /nation?isbn=…` — 경기 광역 소장관 수(전국 예시)
- `GET /health` — 살아 있는지와 키가 있는지만 답합니다. 키 값은 어디에도 내보내지 않습니다.
- `POST /mcp` — 원격 상담 비서(MCP Streamable HTTP). 사람이 인터넷 창으로 열면 안내 화면이 나오고, 프로그램의 GET은 규격대로 405입니다.

<details>
<summary>응답 예</summary>

    /holdings → {"isbn","asof":"2026-10-16","libs":{"141321":"busy",…16관},
                 "calls":16,"upstream_ms":12811,"via":"http","cached":false}
    /search   → {"docs":[{"isbn13","title","author","publisher","year"},…],"asof"}
    /nation   → {"found_count":12,"asof"}
    /health   → {"ok":true,"keyed":true}

</details>

## 4. 배포와 걸리는 시간

**깃허브가 대신 올립니다(10/16~)** — 행정망에서 Cloudflare 화면이 막혀 있어, 배포를 깃허브 액션 `deploy-relay.yml`에 맡겼습니다.

- 저장소 비밀값 `CLOUDFLARE_API_TOKEN` 하나면 됩니다. Cloudflare 「Edit Cloudflare Workers」 템플릿으로 만든 토큰입니다.
- 계정 ID는 선택이며, 없으면 토큰으로 찾습니다. workers.dev 주소 이름이 없으면 만듭니다.
- 중계 파일이 바뀔 때마다 배포하고, 이미 있는 정보나루 키(`NARU_KEY`/`NARUKEY`)를 Cloudflare 비밀값으로 넘깁니다.
- 배포 뒤 네 경로와 원격 상담 비서(상담 1건)를 확인해 `relay/last_deploy.json`에 남깁니다. 주소·결과·실패 까닭만 적고, 키·토큰은 없습니다.

**첫 확인(10/16 17:49)** — 네 경로 모두 200, 시연 웹 출처의 CORS 허용을 확인했습니다. 나미야 잡화점의 기적 16관 조회는 같은 날 새벽 자료와 개수가 같았습니다(대출 가능 7·대출 중 6·미소장 3).

**걸리는 시간(실측)** — 문의 15건을 깃허브 액션(미국 쪽 서버)에서 원격 상담 비서에 보내 쟀습니다.

- **처음(10/16 19:04)** — 그 자리에서 조회한 10건이 가운데값 14.9초였습니다. 정보나루 호출 한 번은 가운데값 1.7초(최대 5.8초)인데, Cloudflare Workers는 요청 1건에서 동시 연결을 6개까지만 엽니다. 그래서 16관 조회가 세 차례로 나뉘었습니다.
- **고친 것** — 16관을 한꺼번에 부르고(소장관 목록 조회 생략), 매뉴얼의 http 주소를 먼저 쓰고, 정보나루 가까이 돌도록 똑똑한 배치(Smart Placement)를 켰습니다.
- **바꾼 뒤(10/17 09:02)** — 그 자리 조회 10건 가운데값 **2.7초**(가장 오래 5.5초), 새벽 자료에 있는 책 5건 0.2초입니다.
- 실측 기록 — `server/lab/out/` 폴더의 `consult_timing_2026-10-16.md`, `consult_timing_2026-10-17.md`
- 그래서 서버는 중계를 20초까지 기다리고, 시연 웹은 3초만 기다린 뒤 새벽 자료로 돌아갑니다.
- 자주 찾는 책은 매일 갱신 목록에 넣어 두면 0.1초로 답합니다.

**브라우저가 아닌 프로그램은 이름을 밝혀야 합니다** — 파이썬 기본 이름(`Python-urllib/…`)으로 부르면 Cloudflare가 `403 error code: 1010`으로 막습니다. 중계 코드가 아니라 Cloudflare의 검사입니다(첫 배포 실측). 참조 서버는 `User-Agent: chaekiji-mcp/0.3.5 (+저장소 주소)`로 부르고, 배포 확인과 운영 점검도 이름을 밝혀 묻습니다. 직접 점검할 때는 이렇게 묻습니다.

    curl -A "chaekiji-relay-check/1.0 (+https://github.com/altarry-prog/chaekiji)" \
         https://chaekiji-relay.altarry2.workers.dev/health

**매일 운영 점검(10/18~)** — 깃허브 액션 `health.yml`이 매일 10:07(한국 시간)에 `relay/health_check.py`를 돌려, 심사위원이 여는 세 곳이 살아 있는지 7가지를 확인합니다.

- 시연 웹 — 배포된 캐시 번호와 첫 화면이 저장소와 같은지, 새벽 자료가 1일 이내인지
- 중계 — `/health`
- 원격 상담 비서 — 인터넷 창으로 열면 안내 화면, 프로그램의 GET은 405, 초기화·도구 목록·판 번호가 저장소와 같은지

정보나루는 부르지 않고(호출 0건) 아무것도 커밋하지 않습니다. 결과는 Actions 탭의 초록·빨강과 요약 표로만 남습니다. 직접 돌릴 때: `python3 relay/health_check.py`

## 5. 실패해도 틀리게 말하지 않기

10/16부터 이렇게 합니다.

- 상류가 안 되면 실패 종류만 돌려줍니다. 예: `502 {"error":"upstream","detail":["https:AbortError","http:503"]}`. 키·주소는 지웁니다.
- 정보나루가 오류 문구(호출 한도 초과·키 오류 등)를 주면, 16관을 「없음」으로 바꾸지 않고 오류로 냅니다.
- 주소마다 기다리는 한도를 둡니다(https 2.5초·http 12초). 한 번 통한 주소는 기억합니다.
- 요청 1건의 외부 호출은 45회 이하입니다(무료 요금제 상한 50).
- 성공 응답에는 어느 주소로 통했는지(https 또는 http)를 `via` 칸에 적습니다.

**알아 둘 것** — 정보나루 키 하나의 하루 한도(500건)를 매일 갱신과 함께 씁니다. 그래서 시연 도서는 새벽 자료로 답해 호출을 아끼고, 같은 책은 10분 동안 다시 묻지 않습니다.

## 6. 지키는 것

설계 원칙 그대로입니다.

1. **인증키는 환경변수(`NARU_KEY`)에만** — 코드·저장소·응답·로그·오류 문구 어디에도 없습니다. 키가 없으면 기동을 거부합니다(503).
2. **허용 출처만 응답** — 시연 웹 `https://altarry-prog.github.io`(+ 로컬 점검 주소)만 받습니다. 원격 상담 비서는 claude.ai도 받습니다. 다른 출처는 403입니다.
3. **정해 둔 경로만** — `/holdings` `/search` `/nation` `/health`와 원격 상담 비서 `/mcp`뿐입니다. 나머지는 404입니다.
4. **호출 상한** — IP당 10분에 60회(429, 상담 1건 = 2~3회)입니다. 같은 조회는 10분 동안 캐시합니다. 서버 relay 모드처럼 브라우저가 아닌 호출은 출처(Origin)가 없어 통과하므로, 이 상한이 남용 방어선입니다.
5. **최소 가공** — 16관의 `ok|busy|none`과 조회일만 내려보내고, 「대출 상태는 조회일 전일 기준」 문구를 붙입니다.

## 7. 연결 — 참조 서버와 시연 웹

**참조 서버(상담 비서)** — 중계 주소를 설정에 넣고 `auto` 모드(기본값)로 띄웁니다.

- 설정 — `server/config/bucheon.yaml`의 `relay_url`, 또는 환경변수 `CHAEKIJI_RELAY`
- 중계가 살아 있으면 키 없이 오늘 데이터로 판정하고, 새벽 자료에 있는 책은 중계 없이 답합니다.
- 부천 설정에는 배포 주소가 들어 있습니다(10/16~).
- 모의 중계로 시험합니다: `python server/tests/run_relay.py`

**시연 웹** — `index.html`의 상수 `RELAY`에 중계 주소를 넣으면 켜집니다. v1.12.2부터 배포 주소가 들어 있고, 빈 문자열이면 새벽 자료와 8. 18. 실측만 씁니다.

    const RELAY = "https://chaekiji-relay.altarry2.workers.dev";

- **순서(v1.12.2~)** — 오늘(한국 날짜) 새벽 자료에 그 책이 있으면 그 파일 → 없으면 중계(3초) → 2일 이내 파일 → 2026. 8. 18. 실측
- 대출 상태는 어차피 전일 기준이라, 낮에 중계로 다시 물어도 새벽 자료와 같습니다. 같은 자료를 두 번 받지 않아 호출 한도를 아낍니다.

## 8. 점검

- 중계 점검 19건 — 정보나루를 흉내 내어 네 경로, 거절 규칙, https→http 넘어가기, 멈춘 주소 끊기, 정보나루 오류 문구, 상류 장애를 봅니다(네트워크·키 불필요). 명령: `node relay/test_worker.mjs`
- 원격 상담 비서 규약 30건 — `node relay/test_mcp.mjs`
- 파이썬 판과 대조 21건 — `python3 relay/test_mcp_parity.py`
- 원격 판 자료가 원본과 같은지 — `python3 relay/build_mcp_data.py --check`
- 실제 주소 운영 점검 7가지(매일 10:07 자동) — `python3 relay/health_check.py`

**설계 문서의 점검 4가지**

1. **허용 출처 밖 요청 거절** — 주소창으로 직접 열면(Origin 없음) 허용, 다른 사이트의 스크립트에서 부르면 403
2. **정해 둔 경로 밖 거절** — `/anything` → 404
3. **키 미설정 시 기동 거부** — 환경변수 없이 실행하면 `relay.py`는 종료, `worker.js`는 503
4. **응답에 키 흔적 없음** — `/health`·`/holdings` 응답 본문에 `authKey` 문자열 없음
