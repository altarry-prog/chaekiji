## 생성된 것
- 중계 `relay/ask.js`: 모든 이용을 KV 저장 공간(chaekiji-ask-records)에 글 없이 세고(날짜·판정 갈래·언어·걸린 시간·기록 여부·점검 호출 여부, 90일), 머리글 `X-Record-Token`이 Cloudflare 비밀값 `ASK_RECORD_TOKEN`과 같은 문의만 문장·답·판정·책까지 기록(90일). `GET /ask/records`(40건씩 이어 받기)·`GET /ask/stats`(날짜별 건수), 둘 다 기록 암호 필요, 한 IP 10분 30번
- 화면 `docs/ask/`: 넓은 화면(960px 넘음) 두 칸(왼쪽 묻기·예시, 오른쪽 답), 「담당자 기록 모드」(기록 암호 넣고 켜기, 기록 내려받기(엑셀에서 열리는 CSV, 알파스 확인 칸 3개 빈칸 포함), 이용 건수 보기, 끄기). 기록 암호는 그 브라우저에만 두고 서버에는 머리글로만 보냄
- 배포 `deploy-relay.yml`: KV 저장 공간이 없으면 만들고 연결, 기록 암호 비밀값을 넘기고, 배포 확인에서 기록 읽기 상태 번호만 남김. 상담 창 정보나루 키는 `NARU_KEY_ASK`·`NARU_KEY3`·`NARU_KEY2`를 차례로 한 번씩 불러 보고 되는 첫 키(승인 전 키는 건너뜀)
- `refresh.yml`: 새벽 갱신은 `NARU_KEY_REFRESH`·`NARU_KEY2`·중계 키 순서
- `naru-keys-check.yml`(수동): 비밀값에 든 정보나루 키들이 서로 다른지·쓸 수 있는지 키마다 한 번 불러 봄(값은 적지 않음)
- 시험 `relay/test_ask.mjs` 30건(모의 저장 공간으로 기록 5건 더함) → 전체 235건

## 사람이 검토·수정한 것
- 개인정보: 다른 사람의 글은 저장하지 않고 건수만. 기록 모드는 담당자 암호가 있는 브라우저만. 창구 기록의 책 이름이 바깥에 나가지 않도록 기록은 공개 저장소가 아닌 KV에 두고, 내려받기는 담당자만
- 정직 고지: 화면 「알아 둘 것」과 README·relay/README의 「저장하지 않는다」 문장을 「글 없이 건수만, 기록 모드만 문장까지 90일」로 바로잡음
- 정보나루 키: 저장소 비밀값은 `NARUKEY`·`NARU_KEY2`(둘 다 정상)와 `NARU_KEY3`(11. 2. 신청, 아직 활성화 전). 코드가 `NARU_KEY2`를 읽지 않아 한 키만 쓰던 것을 바로잡음. 중계(시연 웹·claude.ai 연결·시험 이용 화면)는 `NARUKEY`, 새벽 갱신은 `NARU_KEY2`, 상담 창은 셋째 키가 승인되면 셋째 키(그전에는 `NARU_KEY2`)
- 내려받기 파일 이름은 영문(`chaekiji-ask-records_날짜.csv`): 한글 이름은 일부 브라우저가 「download」로 바꿔 버림
- 숨김 처리 고침: 기록 모드를 켜도 암호 칸이 보이던 것(표시 규칙이 숨김을 덮음)
