# relay/ — 정보나루 중계 (시연 웹이 인증키 없이 실데이터를 쓰기 위한 얇은 층)

시연 웹(깃허브 페이지스)은 정적 페이지라 비밀값을 가질 수 없다. 그래서 **키를 가진 작은 중계**를 하나 두고, 시연 웹은 중계에만 묻는다.
설계와 원칙은 [server/docs/정보나루-중계-설계.md](../server/docs/정보나루-중계-설계.md).

    시연 웹(index.html) ──/holdings?isbn=…──▶ 중계(키 보관) ──▶ 정보나루 Open API
    claude.ai 커넥터 ──POST /mcp(원격 상담 비서)──▶ 중계 ──▶ 정보나루                [10/16]
    참조 서버(server/, relay 모드) ──/search·/holdings·/nation──▶ 중계 ──▶ 정보나루     [v0.3.4]
    중계가 없거나 답이 없으면 → 둘 다 2026. 8. 18. 실측 픽스처로 자동 복귀(화면·안내문에 그대로 표시)

중계 없이도 되는 길이 하나 더 있다 — **매일 갱신**(`server/lab/refresh_today.py` + 깃허브 액션 `refresh.yml`): 정해 둔 도서의 조회분을 새벽마다 받아 `data/holdings-today.json`으로 커밋하면, 시연 웹과 서버(auto 모드)가 그 파일을 읽는다. 대출 상태는 어차피 전일 기준이라 하루 한 번이면 신선도가 같다. 중계는 **목록에 없는 책**(상담 비서의 임의 문의)을 위한 것.

| 파일 | 어디서 돌리나 | 비용 |
|---|---|---|
| `worker.js` | **Cloudflare Workers**(무료) — 깃허브 액션 `deploy-relay.yml`이 올린다(아래). 브라우저 화면에서 붙여 넣고 비밀값 NARU_KEY를 넣어도 된다. 심사 기간 24시간 가동 | 0원 |
| `relay.py` | 도서관 PC·실험실 VM — 파이썬만 있으면 됨(의존성 없음). 개발·검증용 | 0원 |

둘 다 같은 경로·같은 응답(날짜는 `YYYY-MM-DD`):

- `GET /holdings?isbn=9788972756194` → `{"isbn","asof":"2026-10-16","libs":{"141321":"busy",…16관},"calls":16,"upstream_ms":12811,"via":"http","cached":false}`
- `GET /search?q=채식주의자` → `{"docs":[{"isbn13","title","author","publisher","year"},…최대 5건],"asof"}` (제목 부분일치) · `GET /search?isbn=…` → 서지 1건
- `GET /nation?isbn=9788972756194` → `{"found_count":12,"asof"}` (경기 광역 소장관 수 — 전국 예시)
- `GET /health` → `{"ok":true,"keyed":true}` (키 **값**은 어디에도 내보내지 않음)

**배포 주소(2026. 10. 16.~)** — `https://chaekiji-relay.altarry2.workers.dev` (Cloudflare Workers 무료). 첫 확인 기록(`relay/last_deploy.json`, 17:49): `/health`·`/holdings`·`/search`·`/nation` 모두 200, 시연 웹 출처의 CORS 허용 확인. 나미야 잡화점의 기적 16관 조회는 같은 날 새벽 매일 갱신 자료와 개수가 같았다(대출 가능 7·대출 중 6·미소장 3). **걸리는 시간(실측)** — 문의 15건을 깃허브 액션(미국 쪽 서버)에서 원격 상담 비서에 보내 쟀다. 처음(10/16 19:04, `server/lab/out/consult_timing_2026-10-16.md`)에는 그 자리에서 조회한 10건이 가운데값 14.9초였다. 정보나루 호출 한 번은 가운데값 1.7초(최대 5.8초, 19:11 기록)인데, Cloudflare Workers는 요청 1건에서 동시에 연결을 6개까지만 열 수 있어 16관 조회가 세 번에 나뉘었다. 그래서 16관 bookExist를 한꺼번에 부르고(소장관 목록 조회 생략), 매뉴얼의 http 주소를 먼저 쓰며, 정보나루 가까이 돌도록 똑똑한 배치(Smart Placement)를 켰다. 바꾼 뒤(10/17 09:02, `consult_timing_2026-10-17.md`) 그 자리 조회 10건은 가운데값 **2.7초**(가장 오래 5.5초), 새벽 자료에 있는 책 5건은 0.2초. 그래서 서버의 중계 대기는 20초, 시연 웹은 3초만 기다리고 새벽 자료로 돌아간다. 자주 찾는 책은 매일 갱신 목록에 넣으면 0.1초로 답한다.

**브라우저가 아닌 프로그램은 이름을 밝혀야 한다** — 파이썬 기본 이름(`Python-urllib/…`)으로 부르면 Cloudflare가 `403 error code: 1010`으로 막는다(중계 코드가 아니라 Cloudflare의 검사, 첫 배포 실측). 참조 서버는 `User-Agent: chaekiji-mcp/0.3.4 (+저장소 주소)`로 부르고, 배포 확인도 이름을 밝혀 묻는다. 직접 점검할 때(확인된 이름): `curl -A "chaekiji-relay-check/1.0 (+https://github.com/altarry-prog/chaekiji)" https://chaekiji-relay.altarry2.workers.dev/health`

**깃허브가 대신 올리기(10/16~)** — 행정망에서 Cloudflare 화면이 막혀 있어, 배포를 깃허브 액션 `.github/workflows/deploy-relay.yml`에 맡겼다. 저장소 비밀값 `CLOUDFLARE_API_TOKEN`(Cloudflare 「Edit Cloudflare Workers」 템플릿 토큰) 하나만 있으면(계정 ID는 선택 — 없으면 토큰으로 찾고, workers.dev 주소 이름이 없으면 만든다) `worker.js`·`wrangler.toml`이 바뀔 때마다 배포하고, 이미 있는 정보나루 키(`NARU_KEY`/`NARUKEY`)를 Cloudflare 비밀값으로 넘긴 뒤 `/health`·`/holdings` 1건을 확인해 `relay/last_deploy.json`(주소·결과·실패 까닭, 키·토큰 없음)에 남긴다.

점검: `node relay/test_worker.mjs` — 정보나루를 흉내 낸 fetch로 네 경로·거절 규칙·https→http 넘어가기·멈춘 주소 끊기·정보나루 오류 문구·상류 장애 19건(네트워크·키 불필요).

**실패하면 까닭만 알린다(10/16~)** — 상류가 안 되면 `502 {"error":"upstream","detail":["https:AbortError","http:503",…]}`처럼 실패 종류만 돌려준다(키·주소는 지움). 정보나루가 오류 문구(호출 한도 초과·키 오류 등)를 주면 16관을 「없음」으로 바꾸지 않고 이렇게 오류로 낸다. 주소마다 기다리는 한도(https 2.5초·http 12초), 한 번 통한 주소 기억, 요청 1건의 외부 호출 45회 이하(무료 요금제 상한 50). 성공 응답에는 통한 주소 종류 `via`(https|http)가 붙는다.

## 원격 상담 비서 (MCP) — claude.ai 커넥터

**왜** — 행정망 PC처럼 파이썬·설치형 앱을 쓸 수 없는 곳에서도, 인터넷 창의 claude.ai만으로 상담 비서를 쓰게 하려고 만들었다. 심사위원도 설치 없이 1분이면 붙는다.

**주소** — `https://chaekiji-relay.altarry2.workers.dev/mcp` (이 중계 서버의 한 경로, MCP Streamable HTTP · 로그인 없음)

**붙이는 법(claude.ai)**
1. 「사용자 정의 → 커넥터 → + 추가 → 커스텀 커넥터 추가」를 누른다(무료 요금제는 1개까지, 팀·기업 요금제는 소유자만 추가 — claude.ai 도움말).
2. 이름은 「책이지 상담 비서」, 주소는 위 주소 → 「계속」. 인증 방식은 「로그인 없음」 → 「추가」.
3. 새 대화의 「+ → 커넥터」에서 켜고, 이용자의 말을 그대로 적는다. 예: `나미야 잡화점의 기적 빌리고 싶어요, 상동에서 받을게요`

**무엇을 하나** — 파이썬 참조 서버(`server/`)를 relay 모드로 띄운 것과 같다: 찾기 → 관내 소장·대출(오늘 새벽 매일 갱신 자료, 없으면 정보나루를 그 자리에서) → 규정 판정 → 이용자 안내문 → 접수 메모.
- 도구 3종(모두 읽기 전용): `consult_request` · `search_item` · `check_availability` + 프롬프트 `consult`(사서 모드 지시문) + 사용 안내(`instructions`).
- **하지 않는 것**: 접수·취소·위임·알림, 회원 토큰(받으면 거절), 상태 저장(세션 없음). 개인정보를 받지 않는다.
- 설정·픽스처·지시문은 `server/`의 원본을 `relay/build_mcp_data.py`가 `relay/mcp_data.js`로 옮긴다(손으로 고치지 않음 · 어긋나면 시험 실패).

**두 판이 같은 답을 내는지** — `python3 relay/test_mcp_parity.py`가 같은 시나리오(`relay/test_mcp_scenarios.json`, 시험용 모의 값)를 파이썬 판과 원격 판에 넣어 판정·안내문·접수 메모·근거 문구·링크를 글자 단위로 대조한다(18건: 관내 상호대차·바로 이용·예약·책바다·미확정·제외 자료 2종·연결 끊김(예시 값으로 돌아가지 않음)·**소장 조회 실패 → 확인 불가**·**서지 검색 실패 → 확인 불가**·다른 언어·수령관 오류·찾기 2종·소장 조회 2종). 규약 점검은 `node relay/test_mcp.mjs`(26건: 초기화·목록·알림 202·묶음·오류 코드·출처·호출 상한·소장 확인 불가 등).

**알아 둘 것** — 대출 상태는 조회일 전일 기준. 정보나루 키 하나의 하루 한도(500건)를 매일 갱신과 함께 쓰므로, 시연 도서는 새벽 자료로 답해 호출을 아끼고, 같은 책은 10분 동안 다시 묻지 않는다. 호출 상한은 IP당 10분 60회.

## 지키는 것 (설계 원칙 그대로)

1. 인증키는 환경변수(`NARU_KEY`)에만 — 코드·저장소·응답·로그·오류 문구 어디에도 없음. 키가 없으면 기동 거부(503).
2. 허용 출처만 응답 — `https://altarry-prog.github.io` (+ 로컬 점검 주소). 다른 출처는 403.
3. 경로 화이트리스트 — `/holdings` `/search` `/nation` `/health` 넷뿐. 나머지 404.
4. 호출 상한 — IP당 10분에 60회(429, 상담 1건 = 2~3회). 같은 조회는 10분 캐시. 브라우저가 아닌 호출(서버 relay 모드)은 Origin이 없어 통과하므로 상한이 남용 방어선이다.
5. 최소 가공 — 16관의 `ok|busy|none`과 조회일만 내려보냄. 「대출 상태는 조회일 전일 기준」 문구 포함.

## 참조 서버 쪽 연결 (상담 비서)

`server/config/bucheon.yaml`의 `relay_url`(또는 환경변수 `CHAEKIJI_RELAY`)에 중계 주소를 넣고 `CHAEKIJI_MODE=auto`(심사 기본값)로 띄우면, 중계가 살아 있을 때 키 없이 오늘 데이터로 판정한다. 매일 갱신 스냅샷에 있는 책은 중계를 부르지 않는다. 10/16부터 부천 설정에 배포 주소가 들어 있다. 시험: `python server/tests/run_relay.py`(모의 중계).

## 시연 웹 쪽 연결

`index.html`의 상수 `RELAY`에 중계 주소를 넣으면 켜진다(v1.12.2부터 배포 주소가 들어 있음. 빈 문자열이면 매일 갱신 파일 → 픽스처만).

    const RELAY = "https://chaekiji-relay.altarry2.workers.dev";

v1.12.2의 순서: 오늘(한국 날짜) 새벽 매일 갱신 파일에 그 책이 있으면 그 파일 → 아니면 중계(3초) → 2일 이내 파일 → 2026. 8. 18. 실측. 정보나루 대출 상태는 어차피 전일 기준이라, 낮에 중계로 다시 물어도 새벽 자료와 같다 — 같은 자료를 두 번 받지 않아 하루 호출 한도(키 하나를 매일 갱신과 함께 씀)를 아낀다. 어느 쪽이든 결과 화면 출처 줄에 조회일이 찍힌다(「정보나루 실데이터 · 2026. 10. 16. 조회」처럼).

## 점검 항목 (설계 문서의 4개)

| # | 항목 | 확인 방법 |
|---|---|---|
| 1 | 허용 출처 밖 요청 거절 | 브라우저 주소창으로 직접 열면(Origin 없음) 허용, 다른 사이트의 스크립트에서 부르면 403 |
| 2 | 화이트리스트 밖 경로 거절 | `/anything` → 404 |
| 3 | 키 미설정 시 기동 거부 | 환경변수 없이 실행 → `relay.py`는 종료, `worker.js`는 503 |
| 4 | 응답에 키 흔적 없음 | `/health`·`/holdings` 응답 본문에 `authKey` 문자열 없음 |
