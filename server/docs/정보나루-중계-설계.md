# 정보나루 중계(프록시) 설계: v0.3.2 설계, 구현은 다음 판

## 왜 필요한가

시연 웹(chaekiji)은 깃허브 페이지스에 올라간 정적 페이지라 비밀값을 가질 수 없다.
페이지 안에 정보나루 인증키를 넣으면 누구나 소스에서 읽어 가므로, 지금까지 시연 웹은
실측 픽스처(전일 기준)로만 동작했다. 심사위원이 접속하는 공개 데모에서 실데이터
조회까지 보여주려면, 키를 서버 쪽에만 두는 얇은 중계가 하나 필요하다.

구조는 한 줄로 요약된다: 시연 웹 → 중계(키 보관) → 정보나루 공개 API.

## 설계 원칙 (보안 규칙과 동일)

1. 인증키는 중계 서버의 환경변수로만 존재한다. 코드·저장소·설정 파일·응답·로그 어디에도 쓰지 않는다.
2. 허용 출처(Origin) 제한: 시연 웹 주소에서 온 요청만 응답한다.
3. 경로 화이트리스트: 시연에 쓰는 조회 2종(소장·대출 가능 확인, 서지 검색)만 통과시키고 나머지는 거절한다.
4. 호출 상한: 짧은 시간창 기준 상한을 두어 키 소진·남용을 막는다.
5. 응답은 가공 최소화: 정보나루 응답에서 시연에 필요한 필드만 추려 전달하고, "전일 기준" 표시를 함께 내려보낸다.

## 시연 웹 쪽 변경 (최소)

- 조회 주소 상수 1곳을 중계 주소로 바꾸고,
- 중계가 응답하지 않으면 **지금처럼 픽스처(모의) 모드로 자동 폴백**한다. 심사 중
  어떤 이유로 중계가 멈춰도 데모가 깨지지 않는다. 화면에는 실데이터/모의 여부를 그대로 표시한다(정직 고지 유지).
