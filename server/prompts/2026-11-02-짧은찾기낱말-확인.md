## 목적
- 이 작업을 모르는 검토 에이전트의 저장소 점검에서, 시연 도서 찾기 낱말이 정보나루 검색보다 먼저 맞춰지므로 「편의점 인간」을 물으면 『불편한 편의점』으로 답할 수 있다는 지적이 나왔다. 11. 2. 16:20 원격 판에 직접 넣어 그대로 일어남을 확인했다(『불편한 편의점』, 근거 「실측 서지 픽스처」).
- 같은 날 바꾼 키 운영(넷을 차례로)과 README의 「인증키 1개」 문장을 맞추고, 정보나루 호출 주소가 http라는 점을 밝힌다.
- 직원 측정(11. 3.~4.) 전에 정한 정답 기준과 측정 전에 고친 것을 기록지 B에 적는다.

## 생성된 것
- 찾기(`server/connectors/naru.py`와 `relay/mcp.js`가 같은 규칙): 시연 도서에 맞은 찾기 낱말이 3자 이하(「편의점」·「소년」·「온실」·「잡화점」·「설민석」 등)이고 검색어에 다른 말이 2자 이상 더 있으면, 정보나루 서지 검색을 첫 검색어로 한 번만 해 본다. 문의 낱말이 서명·저자에 다 들어 있는 다른 작품(고르는 점수 70점 이상)이 나오면 그 책으로 답하고 근거에 「시연 도서 찾기 낱말 「편의점」만 겹쳐 서지 검색으로 다른 책을 고름」을 붙인다. 결과가 없거나 같은 작품(다른 판)이거나 연결이 안 되면 전처럼 시연 도서로 답한다
- 시험: 두 판 대조 4건(「편의점 인간」 다른 작품, 「잡화점 기적」 같은 작품, 「온실 나오는 책」 결과 없음, 「소년을 위로해줘」 연결 끊김), 원격 규약 1건·중계 모드 1건(짧은 낱말 판단과 기록지 B 12건은 그대로) → 전체 253건
- README 7절 두 곳 「인증키 1개」를 「IP를 등록하지 않은 정보나루 인증키(키마다 하루 500번, 넷을 차례로)」로, relay/README 「알아 둘 것(호출 주소)」
- 기록지 B 「측정 전에 정한 것(11. 2.)」: 6번 「채식주의자」 정답은 작품 기준(판 하나만 보고 갈래가 달라지면 틀림, 메모 「판본」), 8번 「요」 결함과 짧은 낱말 확인을 측정 전에 고쳤다는 것

## 사람이 검토·수정한 것
